# Publication benchmark plan

The retained 73-file matrix is a differential regression suite, not the sole
publication benchmark. It contains 3.40 MiB in total, 31 files below 1 KiB,
and only six files at or above 128 KiB. Keep it because it has found parity and
state-transition defects, but do not generalize its throughput or RSS results.

## Required data classes

1. Keep the 73-file matrix and the 202-file decode corpus for fast per-change
   byte/decode regression gates.
2. Add deterministic streams generated by zstd's `datagen`: incompressible,
   low-compressibility, repetitive, skewed-alphabet, structured records, long
   matches, and boundary sizes around 128 KiB. Store generator commands, seeds,
   hashes, and the zstd revision rather than generated bulk data.
   The repository-owned `generate_release_corpus` tool now supplies five
   freely regenerable baseline classes (zeros, repeated records, deterministic
   random, structured JSONL, and long-distance repetition) without importing
   third-party payloads. Generate the default five-by-64 MiB suite with:

   ```sh
   cargo run --release -p zstd-rs-tools --bin generate_release_corpus -- \
     /tmp/ruzstd-release-corpus
   ```

   This supplements rather than replaces zstd `datagen` and licensed real-file
   corpora.
3. The 211,938,580-byte Silesia suite now covers text, executables, source,
   databases, XML, and medical images. It is acquired from a pinned mirror
   commit, all 12 published MD5 values are verified, and corpus bytes are not
   redistributed. The release results and reproduction procedure are in
   `RELEASE_BENCHMARKS_2026-08-30.md`.
4. Generate at least 1, 8, and 32 GiB streaming inputs without materializing
   them in memory. Record allocator-accounted peak heap and OS peak RSS.
5. Train formatted dictionaries with the current stable zstd CLI from at least
   100 samples and about 100 times the target dictionary size. Also test raw
   content dictionaries, prepared reuse, wrong dictionaries, and corrupted
   dictionaries.

## Reference zstd artifacts

Include or reproducibly generate these artifacts from the reference project:

- zstd `datagen` inputs and seeds;
- the official fuzz corpora for robustness, kept separate from throughput
  claims because most cases are deliberately small;
- valid golden frames and invalid-frame cases from zstd's CLI tests for decoder
  compatibility;
- frames produced at every supported level by current stable zstd and selected
  older stable releases, with and without checksum/content-size/dictionary ID;
- dictionaries trained by the current stable CLI and their exact training
  samples/commands;
- concatenated frames, skippable frames, empty input, RLE-first and raw-block
  edge cases.

For compressor interoperability, every Rust output must decode with current
stable zstd C; a compatibility lane should also use selected older decoders.
Every C-produced valid frame must decode in Rust. Exact Rust/C bytes remain an
oracle for the retained reference modes, not a public compatibility promise.

## Measurement matrix

- Levels: 1, 3, 5, 8, 16, 19, 22, plus the documented default.
- Implementations: proposed Rust, latest upstream ruzstd, current stable zstd C,
  and the original fork-base Rust where its level mapping is meaningful.
- CPU: instructions, cycles, branches, branch misses, wall time, and throughput;
  use medians from repeated same-session runs and preserve raw counters.
- Output: bytes, ratio, decode verification, and frame metadata.
- Memory: peak live heap, allocation count, peak RSS, and failure at an explicit
  memory budget.
- Builds: workspace performance profile, external consumer default release,
  and external consumer `codegen-units = 1`.
- Targets: Linux x86-64 with and without BMI2, Linux AArch64, Windows x86-64,
  macOS x86-64/AArch64, and wasm `no_std`. Thirty-two-bit is deferred.

Performance-sensitive structural changes use a same-binary candidate/control
switch followed by a clean post-removal binary measurement. Microbenchmarks can
explain a cause but cannot by themselves approve a change.
